# TaskCraft

TaskCraft is a single-page study and project planner built with HTML, CSS, and browser JavaScript. Its source is [index.html](./index.html). The optional backend uses Supabase Auth, Postgres, Row Level Security, and an Edge Function for Gemini requests.

## Features

- Dashboard with task totals, completion progress, saved roadmap phases, flashcard totals, a daily streak, and a seven-day completion count.
- Task creation, completion, deletion, priorities, due dates, categories, search, and filters.
- AI learning roadmaps with flowchart and step-by-step views, phase details, prerequisites and tools, and phase-to-task import.
- Flashcards with question/answer flipping, manual creation, and optional AI-generated decks.
- A contextual study and planner assistant.
- Browser-local storage while signed out and private, per-user cloud storage after Supabase setup.
- Offline sample roadmaps, study guidance, and flashcard prompts when cloud AI is not connected. These are labelled as samples; they are not generated by an AI model.
- Responsive layout for mobile and desktop.

## Run locally

You can open `index.html` directly for local-only features. To use Supabase Auth and its Edge Function locally, serve the folder over HTTP instead; from this folder run:

```powershell
py -m http.server 8000
```

Then open <http://localhost:8000>. The Supabase JavaScript client is loaded from a CDN, so an internet connection is needed.

## Connect Supabase and Gemini

Follow [`supabase/SETUP.md`](./supabase/SETUP.md):

1. Run [`supabase/schema.sql`](./supabase/schema.sql) in the Supabase SQL Editor.
2. Replace `SUPABASE_URL` and `SUPABASE_ANON_KEY` in `index.html` with your Supabase Project URL and browser-safe publishable/anon key.
3. Deploy `supabase/functions/ai-assistant` with the Supabase CLI and set `GEMINI_API_KEY` as a server-side secret.
4. Enable Email Auth and configure the correct local/hosted site URLs in Supabase Auth.

Never put a Supabase service-role key or Gemini API key in `index.html` or any public GitHub file. The included database tables have user-scoped RLS policies. Local browser records do not automatically merge into a cloud account.

## Publish on GitHub Pages

This folder is the website project root. From this folder, create a repository on GitHub, then run:

```powershell
git init -b main
git add .
git commit -m "Add TaskCraft study planner"
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

Replace the example remote URL with your new GitHub repository URL. Enable Pages in **Settings → Pages**, choosing **GitHub Actions** as the build/deploy source. The included workflow publishes `index.html` on pushes to `main`.

Supabase and Gemini remain separate hosted services; GitHub Pages only serves the front end. Set the published GitHub Pages URL in Supabase **Authentication → URL Configuration**. For local development, also allow `http://localhost:8000`.

## Project files

- `index.html` — complete front-end application.
- `supabase/schema.sql` — tables, indexes, and user-scoped security policies.
- `supabase/functions/ai-assistant/index.ts` — authenticated server-side Gemini proxy.
- `supabase/config.toml` — Edge Function configuration.
- `supabase/SETUP.md` — Supabase project setup steps.
- `.github/workflows/pages.yml` — GitHub Pages deployment workflow.
